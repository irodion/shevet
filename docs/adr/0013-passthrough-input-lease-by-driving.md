# Input is passthrough-by-default; the Leader is the only reserved key; the Focus Lease follows driving

The original input model was modal: dashboard keys drove the UI, and only entering Focus switched to passthrough. The #11 design review reversed it: in Tiles and Focus, every unmodified keystroke forwards byte-faithfully to the selected/focused Pane's Agent, and every dashboard verb lives behind the single configurable Leader (default `Ctrl-\`) — the tmux/Hyprland contract, "everything is the Agent's except the Leader". Two consequences are deliberate: Enter is an Agent key (answering an Agent's prompt requires it), so Focus is entered by a Leader verb, never Enter; and Agents sit at `proceed? [y/n]` prompts, so we accept the stray-keystroke hazard in exchange for zero-ceremony triage — which is also why tile order must never change except by the developer's own verbs.

The Focus Lease follows the same principle: it is taken by *driving*, not looking. A Client's first keystroke or resize on a Pane steals the lease implicitly, server-side; there is no `AcquireFocus` message, input is never dropped for lease reasons (last-writer-wins), and selection/browsing puts nothing on the wire — so `FocusChanged` telemetry names whoever last actually drove a Pane instead of churning with navigation. Rejected: an armed-input toggle (reintroduces mode-tracking the reversal exists to remove), Status-gated forwarding (the same key changes meaning on an async Status flip — a nondeterministic stray-`y`), and lease-on-selection (browsing from a second Client would silently yank leases).
