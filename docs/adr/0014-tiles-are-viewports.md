# Tiles are viewports onto Panes — the layout never resizes them; only Focus does

The Tiles surface is Hyprland-inspired, but deliberately breaks with Hyprland where our domain differs: a tile is a live, cursor-following viewport onto its Pane at the Pane's real size, and layout operations (navigate, swap, grow/shrink, Herd churn) never touch tmux geometry. Four reasons: a Pane has one real size while N Clients have N viewports and layouts, so layout-driven geometry makes concurrent Clients fight by construction; resize is a driving act under ADR-0013, so resizing on selection would turn browsing into lease-stealing; Adopt promises minimal disturbance — an Adopted Pane accepts input and Focus resize when the developer deliberately drives it, but layout-driven `resize-window` would reshape (and squash siblings in) a session the developer owns elsewhere merely because a dashboard rendered it; and the Herd churns, so every Spawn/exit would reflow every Agent's screen and permanently re-wrap tmux scrollback. Keeping layout Client-local also keeps swap/grow/navigate instant — no wire round-trip inside the hottest interactions — and avoids re-opening the resize-attribution problem the Server-owned RestoreSize design closed.

The accepted cost: tile content is a crop, not a reflow — line wraps match the Pane's real width, not the tile's. Focus, one Leader verb away, is the WYSIWYG surface: the only place a Pane is resized (to the Client viewport minus the Shevet bar) and restored afterward. Rejected middle ground: resize-on-first-drive (the lease-stealing keystroke also resizes the Pane to its tile) — it reflows the Agent's screen under the developer's fingers mid-answer and forces Agents into tiny geometries.
